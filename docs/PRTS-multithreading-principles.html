PRTS 多线程引擎 · 工作原理

在不放弃 NeoForge 模组兼容的前提下，把「无玩家维度的整 tick」「世界实体与方块的区域分片」 「怪物 A* 寻路」三类计算安全地搬上多核——世界权威状态永远留在主线程，所有结果在 tick 边界汇合。

02一句话核心思想

世界状态的权威永远在主线程。我们并行化的不是「整个服务器」，而是三类可以安全离主线程的计算： 无玩家维度的整 tick、实体与方块 tick 的区域分片、以及 A* 寻路搜索。所有结果在 tick 边界汇回主线程应用。

P2维度并行

每个维度一个 tick 单元：没有玩家的维度整段放在 PRTS-DimensionTick-* 线程跑；有玩家的维度留在主线程，保证玩家交互语义。

P3区域并行

把每个维度的世界按区块横坐标切成 N 条竖带（默认 4），实体 tick 与方块 tick 分派到 PRTS-RegionTick-*；跨区写走 1 tick 更新集。

P1异步寻路

怪物 A* 搜索只提交一次只读快照给寻路线程池计算，结果在主线程（或本区域线程）应用。

护栏并发安全体系

barrier + watchdog 感知、线程策略守卫（违例自动回主线程）、实体索引读写锁、worker 安全区块读、跨区写日志 journal、BE 安全阀、主线程专属队列——多线程的核心工作量其实在护栏上。

图 2：模组兼容是红线——worker 永远只算「能安全离主的部分」，世界权威态仍在主线程
实测证据（纯净环境 2000 僵尸）：单线程模式下 JFR 采样 95% 都在 Server thread；多线程全开后 1682 个样本全部落在 PRTS-RegionTick worker，Server thread 0 样本——实体 tick 完整搬离主线程。TPS 两者都满 20，但线程分布才是决定性证据。

08并发安全体系：主线程专属状态 × worker 安全读

绝对不能在 worker 上碰的东西

对象为什么危险
Level.getBlockEntity1.21.1 有线程守卫：非主线程固定返回 null（装置自毁/矿车装配失效的根源）；ThreadPolicy 同时记账，违例实体类自动路由回主线程
ServerChunkCache.getChunkNow非主线程恒 null，曾导致 worker 上全部实体 tick 被静默跳过
Colony / 请求系统 / POI主线程独占可变结构，worker 并发读 = CME / AIOOBE

邻居更新器 / AC 红石图单线程栈式状态 / 全局连线图，并行即损坏

worker 安全读区块的正确姿势

来源规则
visibleChunkMapvolatile 整体替换引用，读旧快照安全
updatingChunkMapholder 的 full-future getNow，不阻塞
二次身份复核visibleChunkMap.get(key) == holder 才相信

铁律：worker 无锁读不得信任「写入后从不失效」的缓存，必须带新鲜度校验。

锁与隔离清单（随事故逐层加固）

机制保护对象要点
实体管理两级锁EntityLookup / EntityTickList / EntitySectionL1 全局索引读写锁（单调用点、从不嵌套）+ L2 per-section 读写锁；getOrCreateSection 无锁快速路径

LegacyRandomSourceServerLevel.random构造换 ThreadSafeRandom + next() CAS 自旋重试（region 开启时）
第三方无锁结构Sable 方块缓存 / AC 红石图@LoadIfMod 兼容 mixin：局部加锁；AC 存在时红石块 tick 回退串行
barrier 健壮性主线程等待watchdog 感知（barrier 内不判卡死）+ 120s 超时全线程 dump 主动崩

09区块生成：唯一驱动在主线程

1.21.1 的 GenerationChunkHolder.completeFuture 存在「一方 complete 失败 + getNow 非成功 → 无限自旋」的路径。 并行 worker 与主线程同时推进同一 chunk future 时，生产服 1 分钟内必 hang。

根治模型（Folia 式）：applyStep / completeFuture 的执行权完全收归主线程。 worker 的 applyStep 被守卫取消；所有线程的 getChunk 需求统一进 ChunkDemandQueue，由主线程作为唯一生成驱动。
闸门作用默认
generation-tasks-per-tick每 tick 最多提交 N 个生成请求50
chunkgen-inflight-limit2s 滚动窗口最多提交 N 次（只限提交，不丢生成）128
chunk-demand-per-tick主线程每 tick 处理的需求数上限50

效果：1024 区块生成风暴的 max MSPT 从 1.5–2.3s → 429ms（↓约 80%）。

主线程 getChunk 在快照未命中时直接回退 vanilla 阻塞路径；worker 才走快照 → 需求 → 空壳兜底。

12踩坑史：每一场崩溃都变成一条机制

  • 08-06/07 · 原型期快照遍历触发 EmptyLevelChunk 构造 → 60s 卡死按 chunk 粒度遍历 + 未加载跳过；快照永远是纯引用拷贝，不触发加载。
  • 08-07 · P3LegacyRandomSource 多线程 CAS 崩溃random 构造换线程安全实现 + next() CAS 自旋；模组「顺手读全局 random」也要兜住。
  • 08-07/08实体索引 fastutil 撕裂（Index -1 / CME）实体管理两级读写锁；type 查找必须写锁（find 内部会写 byClass）。
  • 08-10 · 纯净压测2000 僵尸暴露 navigatingMobs / 邻居更新器并发损坏主线程专属结构逐个加锁；压测实体必须覆盖真实 AI 路径，NoAI 羊会漏报。
  • 08-10RemoveBlockGoal worker 上触发 PerlinNoise 风暴缺失 chunk 兜底喂 THE_VOID 常量，禁止在 worker 上现算噪声。
  • 08-11主线程 getChunk 与 worldgen 竞争 completeFuture → 无限自旋 hang统一异步 chunk 需求调度：applyStep 执行权完全收归主线程（Folia 模型）。
  • 08-13容器闪一下即关玩家 tick 必须在主线程 → dimension-parallel 按「有无玩家」拆分。
  • 08-14漏斗 filter NPE 三连崩 → 真凶是 lastChunk 环形缓存陈旧 chunkworker 读取只信 visible/updating map + 身份复核；永不失效的缓存一律禁用。
  • 08-14列车被拆 / 装置自毁 / 矿车装配失效任何 tick 内调 getBlockEntity 的 mod 实体都必须主线程路由（白名单走查超类链）。
  • 08-14生物不动：异步寻路三连 bug + 原版 getChunkNow 主线程依赖异步化一个状态机前先逐条镜像 vanilla 原调用链语义。
  • 08-14AC 红石图被并行方块 tick 撕裂第三方全局可变图结构与并行不共存 → 运行时检测回退串行。
  • 08-15worker 上 BE tick 越界崩溃（lootr 箱子）单类型故障不该拖垮全服 → BEPolicy allow/force/自动降级 + Throwable 安全阀。
  • 08-15spark：haveTime 占 6.4% active@Inject 的 CallbackInfoReturnable 分配是热点 → @Overwrite 直写字段，热点归零。
  • 08-15/16Create 铁轨曲线单 tick 栅格化 342msBezierConnection.rasterise 逐 tick 摊开 + 块数预算，峰值压到 92ms（可再调 32/16）。

13殖民地 NPC 专项（2026-08-15 已落地）

为什么市民必须主线程

市民 aiStep 每 5 tick 跑工作 AI 状态机（82 个工作类），大量 Level.getBlockEntity；同时读写 Colony 全局状态。worker 上拿不到 BE， Colony 状态会撕裂 —— 所以整个 com.minecolonies.* 走主线程队列。

实测基线（196 市民全员行走）：TPS 20.0，主线程 drain 约 3.6ms/tick。

相位错峰优化

AbstractEntityCitizenMixin_ColonyPhase 把 tickCount % 5 == 0 改为 (tickCount + citizenId % 5) % 5 == 0： 全殖民地工作 AI 从「每 5 tick 集中爆发」摊平成「每 tick 稳定约 1/5」。

开关结果
off早期窗口 avg 6.5ms
on早期窗口 avg 4.1ms（-37%），行为中性

后续候选：可调间隔（5/10/20）、按距玩家远近分层降频。

一句话总结：PRTS 多线程 = 主线程权威 + 三类安全并行（维度 / 区域 / 寻路）+ 多层护栏（barrier、锁、线程策略守卫、跨区写日志、BE 安全阀）+ 一张主线程专属实体白名单。 目标不是「20 → 40 TPS」，而是把 MSPT 稳稳压回 50ms 预算以内。
