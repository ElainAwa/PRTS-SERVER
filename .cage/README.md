# Agent 工作约束（笼子）

> 本文件夹是仓库内所有 AI Agent（下称"你"）的工作约束。开始任何工作前必须完整阅读本文件夹。

## 使用方式

1. 读本文件，记住红线清单（不允许）。
2. 按任务类型读对应分册：`workflow.md`（修 bug / 优化流程）、`architecture.md`（线程与事件语义）、`code.md`（代码 / 配置 / 提交）。
3. 评审：收到任务先按 `workflow.md` §0 输出评审（优点 / 风险 / 理念冲突 / 评分；含并发术语时另出概念判定），用户确认后再动手。

## 红线（不允许，无例外）

1. **不改可观察语义**。事件的数量与时机是 mod 契约：禁止削减、延迟、合并或吞掉事件（尤其 `BlockEvent` 系）；只允许降低单个事件的内部成本。禁止改动 `EventBus.post` 派发本体、禁止事件池、禁止降频合并、禁止跳过「黑盒不可判定」的监听器。
2. **worker 禁碰主线程专用状态**。`getBlockEntity` / `getChunkNow`、Colony / POI、实体索引、邻居更新器、AC 红石图等一律主线程；跨区写只能走 `WorldWriteJournal`（入队、下一 tick 应用、带上限与丢弃计数），`Journal dropped*` 不允许大于 0。
3. **世界权威态永远在主线程**。玩家保持主线程（容器 / 菜单 / 事件）；有玩家维度必须主线程串行。未经维护者同意不得改变归属。
4. **禁止 Folia 式激进并行**（L4/L5 级）；禁止非主线程等主线程执行器。
5. **禁止误短路**。预检 / 短路失败时保守回退为「有监听器」；返回值参与逻辑的事件（伤害、刷怪判定）不短路。
6. **不与同类优化器共存**。检测到 Lithium / Canary / Radium 等必须 `@LoadIfMod(ABSENT)` 让位；红石类改动遇 `alternate_current` 整体回退串行。
7. **禁止改第三方 mod 源码**。兼容逻辑收敛到 `compat/` 命名空间，反射调用必须无编译依赖 + try/catch 空转 + instanceof 兜底 + 幂等。
8. **禁止臆断**。对引擎 / 总线行为的任何断言必须先对照源码或字节码核实；理论热点必须经 spark / JFR 实测证伪后才能立项（教训：`EventBus.post` 占 75.5% 而非 vanilla 热点；「barrier 死锁车队」被源码推翻）。
9. **禁止跳步**。登记 → 取证 → 定位 → 根因 → 修复 → 验证，一步未完成不得进入下一步；复现只在取证不足时使用，不是必经步骤；冒烟测试 FAIL 不得进入下一步。
10. **新能力默认值经评估决定**。新能力（含并行开关）的默认值由头脑风暴 / 评估决定并记录理由，不预设一律 `false`；`thread-policy` 保持 `stats`（只统计不拦截）；`enforce` 仅测试服使用。
11. **禁止静默失效**。改 `arclight-common` 后必须清缓存（`mod_file/*`、`gson.jar`、`class_cache`），并以 `-Dmixin.debug.export=true` 确认注入生效后再验收。
12. **禁止越权发布**。tag / release 由维护者决定，未经授权不发布；协作者在功能分支上按 `code.md` 规范提交自己的改动，不向受保护分支直接强推。
13. **禁止改证据**。仓库内既有分析文档与约束文档是决策与证据链记录，不删不改；新增分析按 `workflow.md` 规范输出为新文档。
14. **禁止未评审即动手**。收到任务先按 `workflow.md` §0 输出评审（优点 / 风险 / 理念冲突 / 评分），用户确认后再执行；用户明确免评审时除外。
15. **禁止在 `1.21.1-Multithreading` 分支上工作**。开工前先查分支（`git branch --show-current`）；若仍处于多线程开发分支，**提醒用户切换分支并终止当前工作**，等用户确认目标分支后再动。禁止带着旧分支上下文继续执行任务。

## 文件导航

- `workflow.md` — 任务受理评审、修 bug 状态机、方案 / 结果归档（`docs/scheme`、`docs/summary`）、A/B 方案文档规范、性能对照口径。
- `capture.md` — 监测文件（抓包文件夹 / zip）识别与处理流程。
- `architecture.md` — 线程模型不变量、事件桥约束、锁纪律、兼容纪律、正确性优先原则。
- `code.md` — 写代码守则、目录与放置规范（优化 / 兼容分放）、配置三件套、可观测性、构建核对、提交规范。
- `concurrency.md` — 异步 vs 多线程概念判定：用户需求里的串并行词汇先拆「问题 vs 手段」，输出 `[ASYNC-VS-THREADS]` 判定与利弊对照。
- `glossary.md` — 术语表：BEPolicy / Journal / drain / cross.read 等专有词标准义，冲突以源码为准。
- `scripts/` — 工具脚本：spark 采样解析（`spark_quick.py`）、RCON 客户端、冒烟测试、字节码抓取 agent。
