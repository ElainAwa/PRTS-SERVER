# 异步 / 多线程概念判定（[ASYNC-VS-THREADS]）

## 1. 为什么要有这篇

用户需求中常把「异步」与「多线程 / 并行」混为一谈。把两者搞混会让改动方向走偏、结果大打折扣：

- 把本来就是 worker 多线程的东西再改「异步」，实际诉求却是「主线程不阻塞」→ 没解决等待，还多引入一层复杂度。
- 反向把「不阻塞」臆断为「多线程」→ 为不需要的并行买单，引入竞态 / 锁 / barrier 成本，触碰红线 2 / 4。
- 认知误区：**「异步」≠「更快」**。异步只是「不占着等」，不开真并行时单核吞吐不变，反而多一层背压 / 延迟。

因此：方案里出现这些词且作为实现手段时，先拆「问题 vs 手段」，别把用户给的手段当问题直接做。

## 2. 触发词

方案中出现以下词汇**且作为实现手段**时必答判定（仅作描述背景，如「测试服上有个线程 dump」，不触发）：

`异步` / `不阻塞` / `非阻塞` / `并行` / `并发` / `多线程` / `多核` / `worker` / `子线程` / `事件循环` / `协程`

## 3. 判定输出（workflow §0 第 4 条）

判定段必须写满四条，缺一不可：

1. **诉求拆分**：真实要解决的是「当前线程（通常主线程）不卡顿」→ *异步候选*；还是「单核算力到顶，需要利用多核」→ *多线程候选*？两条各写一句结论，不许只写一条。
2. **红线内先行**：能否先以不越红线的方式解决——延迟 / 批处理 / 队列 + 预算 / 复用已有 worker？列候选，不直接跳到加线程或改语义。
3. **所选手段的优缺点**：缺点必须写。异步 → 单核吞吐不变 + 需背压 / 丢弃语义；多线程 → 竞态 / 可见性 / 锁序 / barrier，触碰红线 2 / 4 与架构 §8 小步开。对照表见 §5。
4. **取舍结论 + 依据**：一句话裁决，引用红线 / 架构条款；并给两选项各一句「在什么证据下结论会翻转」。

## 4. 决策原则：先异步后并行

1. 用户提「异步」，默认真实诉求是「不阻塞」：先在红线内降事件内部成本 / 队列化 / 延迟读侧占位（`WorldWriteJournal`、`eventbridge`、chunkgen 预算）。
2. 只有评估证明吞吐受单核限制、多核收益可量化（spark 归因显示真实 worker 侧需求）才升级为并行，并按红线 10 做默认值评估 + 架构 §8 小步开。
3. 永远先写「不开并行的方案」再谈并行：并行是最后手段，不是默认手段。

## 5. 对照表

| 维度 | 异步（Asynchronous） | 多线程（Multithreaded / 并行） |
|---|---|---|
| 本质 | 单逻辑线程内错峰：发起后不等待，稍后回调 / 轮询收结果 | 多个线程同时算，用满多核 |
| 解决 | 「卡在等」——等 I/O、等慢任务、等锁 | 「算不过来」——单核吞吐到顶 |
| 换来 | 调用方不阻塞 | 真并行、吞吐提升 |
| 代价 | 总吞吐不变；背压 / 延迟 / 丢弃语义；不利用多核 | 竞态 / 可见性 / 锁序 / barrier 成本 |
| 与本仓架构 | 天然贴近「主线程权威态」：队列 + 预算 + 延迟占位即可 | 触碰红线 2 / 4：worker 禁碰主线程状态、禁激进并行 |
| 本仓抓手 | `WorldWriteJournal`、chunkgen 预算、事件桥内部成本、延迟占位 | `ThreadPolicy` 自动路由、区域 / 维度并行 tick、AsyncPathfinding 池 |

**一句话记忆**：异步解决「不卡」，多线程解决「更快」；分不清时先按异步裁，只有结论是「要更快」才需要真并行 + 完整证据链。

## 6. 典型误判

- `"把寻路改成异步"`：寻路已在 AsyncPathfinding worker 池跑——**它本来就是多线程**。真正值得改的是主线程「等寻路结果 / 消费结果」那段不阻塞（异步侧）；若改「异步」而寻路仍同步占主线程，等于没改等待还加了复杂度。
- `"并行要 barrier 兜底，不如异步绕过"`：本仓 barrier 守护「同 chunk tick 责任唯一」，不是拿来省的；绕 barrier 几乎必回退串行或引入语义改动，红线 5 / 7 兜底。
- `"TPS 低，先并行化"`：TPS 低主因可能是主线程过载 / 停顿 / 正确性违规，见 `capture.md` §3 先定性；并行是能力型方案，不是性能万能药。

## 7. 与既有约束挂钩

- **红线 2 / 4**（worker 禁碰主线程状态、禁激进并行）——升级到多线程时逐条对照。
- **红线 10**（新能力默认值经评估）——新并行开关默认值评估后决定，不预设一律 false。
- **架构 §1 / §8**（主线程权威态、正确性优先、小步开）——并行从局部类型开，盯违规计数。
- **capture.md §3**（先定性再立项）——低 TPS 先定性，别直接并行化。
